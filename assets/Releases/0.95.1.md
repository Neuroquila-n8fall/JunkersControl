# Cerasmarter 0.95.1 — Beta

Release date: **2026-11-08**. Exact Git tag: **`0.95.1`**, without a `v` prefix. This is a GitHub **prerelease**, not the latest stable release.

This beta fixes Wi-Fi recovery after an access-point change and replaces the unreliable telnet console with a proper system log. Heating calculations, configuration format, MQTT topics and existing HTTP endpoints are unchanged.

## Highlights

- **Wi-Fi recovers from a weak access point.** After a router-side disconnect the controller reconnects to the strongest AP it hears at that moment, which can be a distant one while the nearby AP restarts. It now checks again about 60 s after such a reconnect and moves on if the signal is below −67 dBm and a better AP is found. Roaming requires an AP at least **8 dB** stronger, confirmed by **two consecutive scans** (previously 12 dB and −70 dBm in a single scan). Connections, losses and every roaming decision are logged.
- **Reliable system log.** The old telnet writer dropped characters, mixed lines from different tasks and could stall the controller for seconds on a poor connection. Messages are now written as whole lines, telnet output never blocks, and telnet clients' negotiation bytes are ignored.
- **System Log page.** **Utilities → System Log** (`/logs`) shows live messages with level and text filters, the events kept across reboots, and a download button.
- **Events survive crashes.** Errors, warnings and info lines from before a software restart, crash or watchdog reset are kept (4 KB) and each boot is marked, e.g. `▶ Boot #2 · reset: panic`. Power loss and the reset button clear this buffer.
- **Cleaner messages.** Consistent levels and colors (error red, warning yellow, info blue, debug uncolored), subsystem prefixes such as `WiFi:`, `MQTT:`, `CAN:`, and rate-limited repeats for CAN send failures and MQTT retries.

## Compatibility notes

- New endpoints: `GET /api/logs`, `GET /api/logs/persistent`, SSE `GET /api/logs/events` and the page `/logs`. See the [API reference](../API.md#system-log). Like all endpoints they have no authentication: **trusted LAN only**.
- With Debug enabled, the controller no longer prints the whole configuration (including Wi-Fi and MQTT passwords) at startup.
- The MQTT log topic `cerasmarter/log` is unchanged.
- Memory: about 7 KB more static RAM and 16 KB of heap for the log history.

## Installation

Use the assets of this release together; the [0.95.0 notes](0.95.0.md#installation-assets-and-upgrade-procedure) describe each image and the backup procedure.

| Asset | Use |
| --- | --- |
| `firmware.bin` | OTA application update on an existing installation |
| `littlefs.bin` | Matching web frontend (required for the new log page) |
| `cerasmarter-complete.bin` | First installation or full recovery, flashed at `0x0`; replaces configuration |

Update **both** the application and the filesystem, then hard-refresh the browser. `GET /api/info` reports version `0.95.1`.

## Verification and limits

Checked on the isolated test ESP32 over USB and on the LAN:

| Check | Result |
| --- | --- |
| Serial colors and line endings, no mixed lines | passed |
| Telnet greeting, clean output, negotiation bytes and split `reboot` command | passed |
| `/api/logs`, `?since=`, `/api/logs/persistent`, SSE stream, `X-Log-Boot` | passed |
| `/logs` page: live updates, restart marker, no duplicates | passed |
| Event buffer survives software reset, panic and interrupt watchdog | passed |
| Event buffer after reset button / serial auto-reset | cleared (expected; RAM is lost) |

The Wi-Fi recovery change has not yet been exercised against a real access-point failover; it will be validated on the production controller. A real power cycle, brownout and telnet queue overflow were not tested.
