# Cerasmarter 0.95.2 — Beta

Release date: **2026-11-08**. Exact Git tag: **`0.95.2`**, without a `v` prefix. This is a GitHub **prerelease**, not the latest stable release.

This beta fixes CAN decoding problems reported with TA270 room controllers and HMM mixing modules, adds read-only information from the room controller, and improves the CAN Analyzer. Heating calculations and the configuration format are unchanged; one new CAN address is added with a default.

## Fixes

- **Mixed circuit read from the wrong byte (#59).** Mixed-circuit frames are `<circuit> <value>` (2 bytes). The value is now read from byte 1, so feed setpoint and feed temperature no longer show 0.5 °C and the pump no longer always reads "on". 1-byte frames are still read from byte 0.
- **Stale burner, pump and season (#60).** The boiler repeats these only while something sends the `0x0F9` info request. They now become **unknown** after 90 s without a frame instead of showing the last value forever.
- **Brief takeover while a room controller is active (#63).** A timer wraparound let Cerasmarter enable override for about a second, roughly once a minute, and send heating frames alongside the room controller.
- **Wrong date/time sent to the boiler after boot.** Date and time are now sent only after the clock has been synchronized.
- **Wi-Fi roaming scans always failed while connected.** Roaming scans now get up to 10 s instead of the core's 2.4 s.
- CAN decoders ignore remote, extended and too-short frames; an implausible outside temperature no longer stops processing of the remaining frames.

## New

- **Mixed-circuit economy from a TA270 (#61):** new address `CAN.Addresses.MixedCircuit.DayMode`, default `0x415` (`01 00` = economy).
- **Heating economy from the room controller:** `0x253` (night/day button) as `Heating.Economy` and Home Assistant binary sensor **Heating Economy**.
- **Hot-water dial holiday:** on while the boiler's hot-water dial reports 10 °C on `0x204`.
- **Room-controller clock check:** a warning, `General.ControllerClockOff` and a diagnostic Home Assistant sensor when the room controller's clock differs from the real time by more than 5 minutes. It resets to unknown when the controller stops sending. Nothing is sent to the controller.
- **CAN Analyzer:** candidate values for every frame, a distinct-payload view per identifier, and user markers that are included in CSV/JSON exports.

## Compatibility

- **Breaking for MQTT/API consumers:** `GasBurner`, `Pump` and `Season` (MQTT) and `FlameLit`, `Pump`, `Season` (`GET /api/runtime`) can now be `null`. Home Assistant shows them as unknown.
- New fields are `null` until their first frame: `Heating.Economy`, `HotWater.DialHoliday`, `General.ControllerClockOff`, `General.ControllerClockOffsetMinutes`.
- Existing configurations gain `MixedCircuit.DayMode = 0x415` on load. If `0x415` means something else on your installation, point it at an unused ID such as `0x7FF`.

## Installation

Update **both** `firmware.bin` and `littlefs.bin` (the dashboard, CAN settings and analyzer pages changed), then hard-refresh the browser. The [0.95.0 notes](0.95.0.md#installation-assets-and-upgrade-procedure) describe each image and the backup procedure. `GET /api/info` reports version `0.95.2`.

## Verification and limits

- The `can_decoder_test` suite (28 cases) replays frames from the issue captures and from a TA270 recording through the real CAN processing on an ESP32.
- The production controller ran pre-release builds of this code for about two hours. Observed live: takeover behaviour with a TA270 connected and disconnected, the room controller's heating economy and clock warning, the hot-water and heating dial frames, the date/time fix and completed roaming scans. The clock check's reset after unplugging the controller was not observed live.
- **Not tested on a real mixing module** (#59, #61). The mixed-circuit pump-off value is inferred. Vacation and the boiler's eco button are not detected because no frame for them was found.
